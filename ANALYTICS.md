# Analytics & Session Logging

This POC includes comprehensive session logging to track how users interact with the system during the evaluation period.

## What Gets Logged

Every query made through the conversational interface is automatically logged with:

### Query Information
- **User Query**: The natural language question asked
- **Generated SQL**: The SQL query generated by the LLM
- **Execution Time**: How long the SQL query took to run (in milliseconds)
- **Row Count**: Number of rows returned
- **Success Status**: Whether the query succeeded or failed
- **Error Message**: If failed, what went wrong

### User Information
- **User ID & Email**: Who made the query
- **User Name**: Display name of the user
- **Conversation ID**: Groups related queries together

### Context
- **Was Follow-up**: Whether this was a follow-up question
- **Previous Context**: What the previous query was about
- **Response Type**: data, analysis, or error
- **Natural Language Response**: The conversational response shown to the user

### Metadata
- **Timestamp**: Exact time of the query
- **Session Date**: Date only (for daily aggregation)
- **IP Address**: Source IP address
- **User Agent**: Browser/client information

## Analytics Endpoints (Admin Only)

All analytics endpoints require **admin role** authentication.

### 1. Get All Sessions
```bash
GET /api/analytics/sessions

Query Parameters:
  - startDate: ISO date (optional)
  - endDate: ISO date (optional)
  - userId: Filter by user ID (optional)
  - userEmail: Filter by email (optional)
  - wasSuccessful: true/false (optional)
  - limit: Number of results (default: 100)
  - skip: Skip N results (pagination)

Example:
GET /api/analytics/sessions?startDate=2025-10-01&limit=50
```

**Returns**: Array of session logs with pagination info

---

### 2. Get Usage Summary
```bash
GET /api/analytics/summary

Query Parameters:
  - startDate: ISO date (optional)
  - endDate: ISO date (optional)

Example:
GET /api/analytics/summary?startDate=2025-10-01&endDate=2025-11-15
```

**Returns**:
```json
{
  "totalQueries": 1250,
  "successfulQueries": 1180,
  "failedQueries": 70,
  "successRate": "94.40%",
  "totalRowsReturned": 45230,
  "avgExecutionTime": "145ms",
  "uniqueUsers": 12,
  "uniqueConversations": 89
}
```

---

### 3. Get Top Queries
```bash
GET /api/analytics/top-queries

Query Parameters:
  - limit: Number of results (default: 10)

Example:
GET /api/analytics/top-queries?limit=20
```

**Returns**: Most frequently asked questions with:
- Query text
- Count (how many times asked)
- Average execution time
- Success rate

---

### 4. Get Daily Usage
```bash
GET /api/analytics/daily-usage

Query Parameters:
  - startDate: ISO date (optional)
  - endDate: ISO date (optional)
  - limit: Number of days (default: 30)

Example:
GET /api/analytics/daily-usage?limit=30
```

**Returns**: Daily breakdown showing:
- Total queries per day
- Successful queries
- Unique users per day
- Average execution time

---

### 5. Get User Activity
```bash
GET /api/analytics/user-activity

Query Parameters:
  - limit: Number of users (default: 20)

Example:
GET /api/analytics/user-activity?limit=10
```

**Returns**: Per-user statistics:
- Total queries
- Success rate
- Average execution time
- Last activity timestamp

---

### 6. Export Data
```bash
GET /api/analytics/export

Query Parameters:
  - format: json or csv (default: json)
  - startDate: ISO date (optional)
  - endDate: ISO date (optional)

Example:
GET /api/analytics/export?format=csv&startDate=2025-10-15
```

**Returns**: Downloadable file with all session logs

**CSV Format**: Includes all key fields in spreadsheet-friendly format
**JSON Format**: Complete raw data export

## Use Cases

### 1. Monitor System Performance
Track execution times and success rates to identify:
- Slow queries that need optimization
- Common failure patterns
- System load over time

### 2. Understand User Behavior
See how users actually interact with the system:
- What questions do they ask?
- Which features get used most?
- Are follow-up questions working well?

### 3. Demonstrate Value
Generate reports showing:
- Total queries answered
- Time saved (vs manual SQL writing)
- User adoption metrics
- Success rate improvements

### 4. Identify Training Needs
Find patterns that indicate:
- Users asking the same questions repeatedly
- High failure rates for certain query types
- Gaps in the data or functionality

### 5. Post-POC Analysis
After the evaluation period (until Nov 15, 2025):
- Export all data for analysis
- Create executive summary reports
- Identify ROI and benefits
- Plan production deployment based on real usage

## Example: Generating a Monthly Report

```bash
# 1. Get summary statistics
curl -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  "http://localhost:8000/api/analytics/summary?startDate=2025-10-01&endDate=2025-10-31"

# 2. Get top 10 questions asked
curl -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  "http://localhost:8000/api/analytics/top-queries?limit=10"

# 3. Get daily usage trends
curl -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  "http://localhost:8000/api/analytics/daily-usage?startDate=2025-10-01&endDate=2025-10-31"

# 4. Export full data for detailed analysis
curl -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  "http://localhost:8000/api/analytics/export?format=csv&startDate=2025-10-01&endDate=2025-10-31" \
  -o october-2025-sessions.csv
```

## Privacy & Security

- ✅ All analytics endpoints require **admin authentication**
- ✅ Session logs are stored in MongoDB with proper indexes
- ✅ No sensitive data (passwords, tokens) is logged
- ✅ Logs can be exported and cleared after POC period
- ✅ IP addresses are logged for security/debugging only

---

## Database Cleanup

After the POC period ends (November 15, 2025), you can clean up session logs:

```javascript
// Delete all session logs
db.sessionlogs.deleteMany({});

// Or delete logs older than a certain date
db.sessionlogs.deleteMany({
  timestamp: { $lt: new Date('2025-11-15') }
});
```

---

## MongoDB Indexes

The following indexes are automatically created for optimal query performance:

- `userId + timestamp` (user activity queries)
- `sessionDate` (daily reports)
- `wasSuccessful + timestamp` (success rate tracking)
- `conversationId` (conversation analysis)
- `userEmail` (user lookup)
